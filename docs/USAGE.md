# Команды и поведение Pivo

Полный перечень с названиями пунктов меню и алиасами: [COMMANDS.md](COMMANDS.md).

## Запуск и сессии

`pivo` открывает оболочку в текущем каталоге, `pivo --continue` продолжает последнюю
сессию, `pivo -s SESSION_ID` открывает конкретную. `/resume` открывает список сессий
(заменяет `/sessions`). Обычные OpenCode-команды доступны через `Ctrl+P` и `pivo --help`;
набор зависит также от твоих custom commands и plugins.

## Отображение

- `/thinking`: скрыть/показать reasoning; меняется только рендер, не запрос и не история.
  Нижняя анимация работы остаётся. Ключ `pivo_thinking_mode`.
- `/sidebar`: показать/скрыть правую панель (таймер, контекст, MCP). Это тот же
  переключатель, что Show/Hide sidebar в `Ctrl+P`; на узком экране панель открывается
  поверх чата. Доступно в сессии; в дочерних чатах sidebar не рендерится.
- `/tools`: показать/скрыть инструменты; ошибки и текущие вызовы остаются заметными.
- `/important`: все инструменты / только важные. Изменения, shell, вопросы, неизвестные
  внешние действия и ошибки показываются краткими раскрываемыми строками; чтение и поиск
  скрыты. Вложенные `execute` учитываются. Ключи `pivo_tool_details_visibility` и
  `pivo_important_tools` отделены от upstream-настроек.
- `/width`: ползунок 40–100%, drag/стрелки/Home/End и пресеты 60/80/100. Минимум 40
  колонок там, где позволяет терминал. Чат и ввод центрируются вместе; sidebar отдельно.
  Enter/Esc закрывают диалог **с сохранением** preview, а не отменой. Ключ `pivo_content_width`.
- `/themes`: `pivo-claude`, `pivo-amber`, `pivo-ember`, `pivo-cocoa`, `pivo-olive`.
  `claude-pivo-orig` устанавливается из `themes/tui` — только голубые акценты исходной темы
  заменены на оранжевые. Ключ `pivo_theme`; явный `theme` в TUI config имеет приоритет.
  Warp-темы устанавливаются отдельно, активная тема автоматически не переключается.

## Таймер справа

«Время агента» находится над контекстом/MCP в правом sidebar. Во время работы обновляется
раз в секунду; после финального ответа показывает сохранённую длительность. Формат `M:SS`
или `H:MM:SS`, без сброса после 24 часов. Sidebar можно включить через Command Palette;
на узком терминале он скрывается стандартным layout оболочки.

Начало — первый assistant-ответ на данный пользовательский запрос. Tool rounds и retries
входят во время; ожидание в очереди до начала обработки не входит. Новый обработанный
пользовательский запрос начинает новый отсчёт; просто добавленный в очередь текст его не
сбрасывает. Это elapsed time, включая ожидание инструментов и разрешений, не CPU time.
После возобновления сессии используются сохранённые timestamps. Для оборванной истории
без надёжного завершения показаны «Остановлен» и `—` либо нижняя оценка `≥`, а не бесконечно
растущий таймер. Это не watchdog соединения: если сервер сообщает `busy`, счётчик продолжает идти.

## Очередь и `/steer`

Enter во время работы сохраняет сообщение в очередь. `/steer`, `Cmd+Enter`,
`Ctrl+Alt+Enter` или `Ctrl+X`, затем Enter подтверждают её доставку на следующей
безопасной границе — после текущего шага модели и запущенных им инструментов.
Можно кликнуть подпись возле `QUEUED`. Черновик этим действием не отправляется.

В **pivo.5** это больше не interrupt: shell и дочерние задачи не отменяются. История и
вложения не пересоздаются; повторное нажатие не порождает дублей. Обычный runner этой
версии и так перечитывает сохранённую очередь на границе шагов: кнопка не обещает
внедрить текст внутрь уже отправленного запроса. Если родитель ждёт долгого сабагента,
уточнение дождётся его результата. Уже работающие сабагенты не получают его автоматически.
Для немедленной остановки используй штатный interrupt. При attach нужен сервер этой
версии Pivo; старый сервер может иметь прежнюю отменяющую реализацию `/steer`.

## Сабагенты

`/subagents` или `Ctrl+X`, затем J: список дочерних задач, состояние, переход к истории
и результату, выбор роли и ручной запуск. В список попадают и задачи, созданные моделью.
Запуск идёт через штатный `subtask` → `task`, сохраняет permissions роли и возвращает
результат родительской модели. У занятого родителя запрос встаёт в очередь. Чтение
списка не вызывает модель; выполнение самой задачи расходует обычную квоту провайдера.

## `/usage`

Локальный диалог квоты ChatGPT/Codex использует OpenAI OAuth из общего `auth.json`.
Запрос идёт в `https://chatgpt.com/backend-api/wham/usage`, без model call. Показаны
остаток и локальное время сброса окон; недельное окно определяется длиной, не позицией.
Отсутствие данных не означает 100%. Истёкший OAuth требует повторного входа через
`pivo auth login`; диалог не обновляет refresh token самостоятельно.

Endpoint не является стабильным публичным API: при изменении upstream возможна ошибка
диалога, она не должна маскироваться выдуманной квотой. См. MIT-проект
[opencode-quota](https://github.com/slkiser/opencode-quota) и OpenAI Codex app-server
`account/rateLimits/read` как источники контракта окон. Plugin 5.x не включён: он требует
OpenCode 2.x/OpenTUI 0.5.x, а эта сборка использует OpenTUI 0.4.5.

## Исправления layout

Pivo.4: числовой `width` OpenTUI сбрасывал `flexShrink`, ввод уходил за нижнюю границу.
Колонка использует `width="100%"` и числовой `maxWidth`; проверка рендерит настоящую
форму ввода, длинную историю, многострочный ввод и разные размеры терминала.

Warp: строка emoji 22px при default line-height 1.2 была выше слота 24px и не рисовалась.
Для кружки задан line-height 1.0; остаются штатные левый отступ и размер слота.

Компактная подпись с настройкой Branch теперь показывает `папка · ⎇ ветка`. Если Git
нет — только папку; если папка ещё неизвестна — только ветку. Остальные варианты
настройки подписи не меняются. Нижний toolbar внешних CLI включён отдельно от Warp
Agent: вложения, каталог и Git-контекст сохраняются. Возвращён штатный shortcut
`terminal:open_cli_agent_rich_input`; override `none` для него не устанавливается.
